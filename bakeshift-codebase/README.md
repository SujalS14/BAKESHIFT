## 2. Final Product Design — Strict Engineering Specifications

All visualizations (hero render, 3D configurator, exploded view, product gallery, and diagrams) adhere strictly to the engineering source of truth:

### 1. Main Baking Pan
- **Material**: Commercial Heavy-Gauge Aluminized Steel (hot-dip aluminum-silicon alloy on steel).
- **Exterior Dimensions**: 15" L × 10" W × 2" H (381 × 254 × 50.8 mm).
- **Provisional Interior Dimensions**: 13.2" L × 9.0" W (335.3 × 228.6 mm) usable floor.
- **Design**: Rounded corners, flat uninterrupted bottom, two integrated side handles, metallic silver/gray finish.
- **Alignment Guides**: Shallow laser alignment marks spaced 1 inch apart along the rim (~2 mm wide × 0.3 mm deep). **Not drilled holes**; designed to assist square partition alignment.

### 2. Removable Cupcake Tray
- **Material**: Commercial Aluminized Steel.
- **Footprint**: 6.25" × 8.70" provisional footprint; sits at the left end of the assembled pan.
- **Arrangement**: **EXACTLY SIX CUPS IN A 2 COLUMNS × 3 ROWS GRID** in every view.
- **Cup Dimensions**: Top diameter ~2.30", bottom diameter ~1.75", depth ~1.25", center-to-center spacing ~2.45", outer perimeter rim 0.75".
- **Hardware**: Two lunch-box style wire toggle clasps mounted to opposing short ends.

### 3. Two Removable Partitions
- **Material**: Commercial Aluminized Steel (plain metallic sheet metal, ~0.9 mm thickness).
- **Quantity**: 2 independently adjustable and fully removable partitions.
- **Dimensions**: 8.9" L × 1.65" H provisional.
- **Silicone Policy**: **ABSOLUTELY ZERO SILICONE, RUBBER, OR TEAL COMPONENTS**. Plain metallic metallurgy that will not warp, melt, or impart odors.
- **Partition Clasp Hardware**: Exactly two toggle clasps per partition (one at each end) facing **OUTWARD** toward the exterior pan rim. Demonstrates how tension secures onto the pan rim.

### 4. Toggle Clasp Hardware Summary
- **Total Clasps**: **EXACTLY SIX TOGGLE CLASPS TOTAL** (2 on cupcake tray, 4 on the two partitions).
- **No clasps** placed on empty rim segments or random corners.
- **Construction**: Proposed AISI 304 stainless-steel wire bail loop and stamped lever with copper-toned mounting rivets.
- **Exploded Behavior**: Clasps remain physically attached to their respective removable components during exploded animations.

## 5. Technology Stack & Architecture

- **3D Graphics Engine**: Three.js (r160) WebGL PBR shaders, ACESFilmic tone mapping, PCFSoftShadowMap, and OrbitControls.
- **Architecture**:
  - `js/bakeshift-bundle.js`: Universal, self-contained application bundle loaded by `index.html`. Runs smoothly across HTTP web servers and direct `file://` local browser opening without CORS blocking.
  - `js/app.js`: Modular ES module architecture importing from `bakeshift3d.js`, `cart.js`, `data.js`, and `story.js`.
- **Cart State**: Reactive store with LocalStorage persistence and subscriber pattern for real-time badge and drawer updates.
- **CSS Design System**: Apple-inspired minimalist design tokens, responsive typography clamps, glassmorphism headers, and smooth transitions.

## Stripe Sandbox / Test Mode Integration

The checkout preview features an embedded Stripe Sandbox integration enabling developer and investor demonstrations without processing live payments.

### Environment Variables (.env)
```bash
# Stripe Sandbox Secret Key (begins with sk_test_)
STRIPE_SECRET_KEY=sk_test_...

# Stripe Publishable Key (begins with pk_test_)
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...

# Optional Price ID for BAKESHIFT Complete Baking System ($59.99 USD)
STRIPE_PRICE_ID=price_...
```

### Security & Safety Barriers
- **Live Key Prohibition**: Any key starting with `sk_live_` is immediately rejected with HTTP 403 Forbidden.
- **Server Price Enforcement**: Unit amount is strictly set to $59.99 USD (5999 cents) server-side; client price tampering is impossible.
- **Secret Key Protection**: `STRIPE_SECRET_KEY` is only read on the server and is never sent to the browser or committed to version control.

### Official Stripe Test Cards
- `4242 4242 4242 4242`: Standard successful payment simulation.
- `4000 0000 0000 0002`: Card declined (`card_declined`).
- `4000 0000 0000 0069`: Card expired (`expired_card`).
- `4000 0000 0000 0127`: Incorrect CVC (`incorrect_cvc`).
